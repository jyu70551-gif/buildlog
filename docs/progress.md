# BuildLog 진행 기록

가장 최근 작업이 위에 옵니다. 기능 범위는 `PRD.md`, `spec.md`, `plan.md`를 따릅니다.

## 2026-10-26 Phase 2, Phase 3 완료

### 완료한 것

**Phase 2. 사용자 데이터 구조와 첫 데이터베이스**
- 데이터베이스는 내부 SQLite3(`database/buildlog.sqlite3`)로 연결했습니다. Supabase 연결은 아직 하지 않았습니다. (Phase 14)
- 사용자 구조: 이메일(중복 불가), 닉네임(중복 불가), 안전하게 처리한 비밀번호(argon2), 운영자 여부(기본 아님), 가입 날짜·시간
- 마이그레이션(Alembic) 첫 파일을 만들고 개발용 데이터베이스에 적용했습니다.
- 자동 테스트는 매번 새 임시 SQLite 파일에서 실행합니다. 개발용 데이터 파일은 건드리지 않습니다.

**Phase 3. 회원가입·로그인·닉네임 변경**
- 서버: 회원가입, 로그인, 내 정보 보기, 닉네임 변경 (`/api/accounts/...`)
- 입력 규칙(spec 2.1~2.3): 이메일 형식과 중복, 비밀번호 8~64자(공백 제거 안 함), 닉네임 2~20자와 허용 문자, 앞뒤 공백 제거
- 로그인하지 않은 요청은 거절합니다. 로그인 확인 값(토큰)은 로그아웃할 때까지 유지됩니다(유효 기간 365일).
- 화면: 회원가입, 로그인, 계정 설정, 내 기록 홈, 위쪽 메뉴(로그인·가입 화면에는 없음), 로그아웃, 로그인하지 않으면 로그인 화면으로 이동
- 실패 시 입력값 처리: 가입은 이메일·닉네임을 남기고 비밀번호만 지움, 로그인은 이메일을 남기고 비밀번호만 지움, 닉네임 변경은 입력값 유지

### 확인한 것
- 서버 자동 테스트 64개 통과, 화면 자동 테스트 14개 통과, 화면 빌드 성공
- 실제 서버를 켜서 확인: 가입, 중복 이메일·닉네임 거절, 비밀번호 7자 거절, 잘못된 로그인 거절, 로그인 없이 접근 거절, 닉네임 변경, 서버를 껐다 켠 뒤에도 같은 로그인 값과 비밀번호로 접속, 허용된 화면 주소만 요청 가능
- 비밀번호 원문이 저장되지 않고 `$argon2id$...` 형태로 저장됨
- 개발용 데이터베이스에는 사용자가 0명이고, 마이그레이션 버전이 적용됨 (확인용 가입은 임시 데이터베이스에서 했고 지움)

### 확인하지 못한 것
- 실제 브라우저(Chrome 등)에서 화면을 직접 눌러 보는 확인. 화면 동작은 자동 테스트(가짜 서버 응답)와 서버 직접 요청으로만 확인했습니다.
- 휴대폰 크기 화면과 Edge·Safari 확인 (Phase 12)
- Supabase(PostgreSQL)에서의 동작 (Phase 14)

### 정한 세부 사항 (spec에 직접 없음, 바꾸고 싶으면 알려 주세요)
- 닉네임의 "한글"에는 완성형 글자(가나다)와 자음·모음(ㅋㅋ)을 모두 허용했습니다.
- 이메일은 대소문자 구분 없이 도메인 부분만 소문자로 정리합니다. 아이디 부분은 입력한 그대로 구분합니다.
- 로그인 실패 안내는 이메일이 없을 때와 비밀번호가 틀릴 때 같은 문구입니다.
- 가입 후 로그인 화면에 "회원가입이 끝났습니다. 로그인해 주세요." 안내를 보여줍니다.
- 로그인 확인 값은 브라우저 저장 공간(localStorage)에 보관합니다.
- 메뉴의 공부 기록·할 일·오류 기록·공개 기록은 아직 "준비 중" 화면으로 연결됩니다.
